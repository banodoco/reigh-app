# Runtime restart and Astrid relaunch

Bind one existing absolute support root and retain its selected realm. Set the same ASTRID_SUPPORT_ROOT and ASTRID_RUNTIME_DATA_ROOT, and set ASTRID_WORKSPACE_DISCOVERY to that root's runtime/discovery.json. An explicit discovery path takes precedence. Runtime discovery is independent of ASTRID_CHECKOUT, which selects source inputs. Conflicting support roots fail before launch. Existing roots and user data are not relocated.

Save the project and record its project/object identities before a supported Runtime stop/restart using the same profile and data root. Close the prior Astrid launcher and browser session. The discovery proxy can follow an endpoint, but the browser's expected instance remains bound to its launch/build; it must not silently accept another Runtime instance.

For development, run `npm run dev:local -- --check`, then `npm run dev:local` against the unchanged selected discovery path. The launcher verifies the product credential, catalog/realm root, health instance, handshake actor/realm/scopes and generated schema before starting Astrid. Relaunch rereads current discovery and supplies the new exact expected instance.

For a delivered preview, run `npm run dev:local -- --build` after source inputs settle. This verifies the same current Runtime identity and passes its non-secret expected actor/realm/instance values to the Vite build, then verifies Runtime identity again after the build. It does not start proxy, ACP or connector services. A Runtime change during the build fails the handoff. Build output defaults to the repository's dist directory. Then run `npm run dev:local -- --preview --preview-dir /absolute/path/to/dist` and open a new browser session. Rebuild again after every instance change; setting environment only when serving an old dist does not update compiled VITE identity.

The delivered browser must actually complete its own matching handshake and read the same saved project/object after relaunch. A successful launcher or build is not that acceptance proof. Retain wrong-realm, wrong-actor and wrong-instance negative checks. Actual dev and delivered preview transition qualification occurs after the settled source build. Seamless live reconnect is not promised.
